The shift

AI stopped being a place you ask questions.

The limit on useful AI was never the model. It was context. An assistant that cannot see your files, your tickets, your documents or your data can only ever give you a well-written guess. This is true whether you write code for a living or have never opened a terminal.

01 — Where it started

Individuals, in a chat box

People write, research, summarize and brainstorm. It works, but every answer starts from zero because the tool knows nothing about your company.

02 — What changed

Context and tools arrived

MCP gave models a standard way to reach real systems. Agents gained the ability to take multi-step action, not just produce text.

03 — Where it lands

A workspace, not an assistant

Sessions that run in isolated branches, tools you connect yourself, knowledge you package once, and controls an administrator can actually enforce.

One workspace. Anyone in it.

Same app. Same pattern. Whatever your job is.

Nobody has to write code to get value here. The pattern never changes: give the app context, describe the outcome, review what comes back. The five tabs below are examples, not a list of who is allowed in. Swap in your own systems and the shape of the work stays the same. From assistant to agent

From asking AI questions to getting work done.

An assistant returns text. An agent plans, calls tools, produces an artifact, and hands it back in a form you can check. The difference is whether anything actually changed when it finished.

1

Task

From an issue, a pull request, a schedule, or a sentence you typed.

2

Plan

In Plan mode the agent proposes its approach and waits for approval before touching anything.

3

Tools

Reads the repo, calls MCP servers, runs commands, loads any skill relevant to the task.

4

Artifact

A pull request, a canvas, a document, a report. Something durable, not a chat message.

5

Handback

You review the diff or the canvas. Work continues in the open, in the systems you already use.

Your company's AI layer

Customization your teams own. Controls your administrators keep.

The reason this can be a company-wide layer rather than five disconnected AI subscriptions is that the customization is version-controlled and the governance is real.

Skills Shipped

Folders of instructions, scripts and resources that Copilot loads when relevant. A SKILL.md with a name and description, plus whatever supporting files you need. They live in .github/skills/ for a project or ~/.copilot/skills/ for a person, and they work across the app, the CLI, the cloud agent, code review and VS Code.

Custom agents Shipped

Specialized versions of the agent that follow your standards and use a defined tool set. Markdown profiles in .github/agents/ per repository, or in the organization's .github repository. Enterprises can designate a .github-private repository and lock it with rulesets so only enterprise owners can change agent profiles.

Plugins Shipped

One installable package that bundles agents, skills, hooks and integrations behind a plugin.json manifest. This is how a capability stops being one person's local setup and becomes something the whole company installs.

Canvases Shipped

Shared interactive surfaces for a work artifact: a plan, a triage board, a browser session, a release checklist, a dashboard. Bidirectional, so the agent updates the canvas while it works and you edit the same surface.

MCP governance GA Registry in preview

Administrators allowlist or deny MCP servers through managed-settings.json, matched by name, URL or command, failing closed and overridable per enterprise team. A self-hosted MCP registry also exists, in public preview, with weaker enforcement. Note the scope: the "MCP servers in Copilot" policy governs Copilot Business and Enterprise members only, not Free, Pro, Pro+ or Max users.

Models and residency Auto GA BYOK preview

Models from OpenAI, Anthropic, Google, xAI, Moonshot AI and Microsoft, selectable per session alongside Auto model selection. Administrators can restrict which models are available, including data-residency and FedRAMP restrictions. Bring-your-own-key is in public preview in the app and supports Azure OpenAI, Microsoft Foundry, Ollama, LM Studio and any OpenAI-compatible endpoint.
